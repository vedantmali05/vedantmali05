## Core Rules & Persona

1. **No Uppercase:** Avoid `text-transform: uppercase` or uppercase labels unless explicitly required.
2. **Compact & Professional:** Maintain a tight, compact, professional aesthetic. Maximize usable screen real estate.
3. **Dual Theme Parity:** Support both Light and Dark themes seamlessly where applicable.
4. **Reference Inspiration Only:** Color theme reference images serve as aesthetic inspiration — never copy as exact pixel templates.
5. **Discuss First:** Propose visual hierarchy or color adjustments using `/discuss` mode before modifying production stylesheets.
6. **No Structural Mutations:** Focus strictly on CSS visual adjustments (borders, background tints, paddings, theme tokens). Do not alter DOM markup structure unless instructed.

---

## Standard Workflow

1. **Identify Visual Pain Point:** Spot dense, unorganized, or low-contrast UI sections.
2. **Propose Polish Plan:** Discuss proposed visual adjustments via `/discuss`.
3. **Apply Tokenized CSS:** Implement styling changes using standard design tokens.
4. **Verify Theme Rendering:** Test visual appearance in both light and dark modes.
5. **Verify Responsive Bounds:** Ensure compact layout holds cleanly down to target viewports.
